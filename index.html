Rolling out AI-assisted development, in stages

CNET Shopping · 2026 · Engineering Manager & Technical Owner

Problem
We wanted AI coding agents to speed up delivery without lowering the bar for quality or review.
What I did
Introduced Claude Code step by step: test runs and code reviews first, then planning, then coding. Plans were accepted only when they fit the product roadmap. When large tickets produced pull requests too big to review properly, I traced it to ticket size and capped changes at 6–7 files. Every PR still gets a human reviewer, and tests and UAT run on dev before anything ships.
Result
About 30% more tickets per sprint, with no drop in quality.
Still open
Human review is now the slowest step, and that's the next thing to improve.

Side project

Job Fit Agent Working · in evaluation

TypeScript · Claude API (Opus 5.5 agent, Haiku 5.5 judge) · MCP · Postgres with pgvector

Problem
Judging fit for a role means checking every requirement against real experience, and AI tools are quick to fill gaps with things that never happened.
What I built
An agent that reads a job posting, searches my CV and work stories through an MCP server (local embeddings in Postgres with pgvector), rates each requirement strong, partial or gap, and drafts tailored CV bullets. Every claim must cite a passage the agent actually retrieved; code downgrades anything that doesn't, and the match score is calculated from the ratings rather than picked by the model.
How I test it
A retrieval check (10/10), then an evaluation suite on 7 live postings. A second model checks every claim against its cited passages, and it first has to catch a set of deliberately fabricated claims (5/5).
Result
All 141 claims backed by their citations, no invented bullets, 7 of 7 clean runs, about $0.31 per posting.
Still open
13% of ratings were more generous than the evidence. Next I'm measuring how closely the agent's ratings match my own.
